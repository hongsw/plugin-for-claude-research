# Evolution-Gated Learning (EGL) — 진화 게이트 학습법

> **Evolution-Gated Learning (EGL)**은 실제 프로젝트의 아키텍처 진화를 커리큘럼으로 삼고,
> 각 진화 단계에 학습 게이트(STOP 프로토콜)를 설치하여,
> 도구가 자기 자신을 가르치는 재귀적 학습 구조를 만드는 교육법입니다.

---

## 정의

**Evolution-Gated Learning (EGL)** — 진화 게이트 학습법

실제 프로젝트의 시간순 아키텍처 진화를 학습 내러티브로 삼고,
각 진화 단계 사이에 강제 게이트(평가 + 피드백)를 설치하며,
학습 도구 자체가 교사 역할을 수행하는 AI 네이티브 교육 방법론.

```
Evolution  ─  실제 프로젝트의 아키텍처가 시간순으로 진화한 경로가 곧 커리큘럼
Gated      ─  각 진화 단계 사이에 STOP 프로토콜(2턴 구조)이라는 강제 게이트 존재
Learning   ─  도구=교사=학습대상의 재귀적 구조에서 자기주도 학습이 일어남
```

---

## 5대 구조적 원칙

### 1. 진화 내러티브 (Evolution Narrative)

> "커리큘럼은 설계하는 것이 아니라, 실제 프로젝트가 이미 걸어온 길이다."

실제 프로젝트의 아키텍처 진화 역사가 1:1로 학습 블록에 매핑됩니다.
교육 과정을 인위적으로 설계하는 것이 아니라, 프로젝트가 실제로 겪은 진화를 재현합니다.

```
실제 프로젝트 진화              학습 블록
────────────────────────────────────────
bash 스크립트         ←→  Block 0: 환경 설정
if/else 조건문        ←→  Block 1-2: 체험 + 이해
역할 분업 멀티에이전트  ←→  Block 3: 7대 핵심 기능
도메인 특화 + 안정화   ←→  Block 3: Hook, MCP
LLM 통합             ←→  Block 5: Skill 제작
RAG + 경험 메모리     ←→  Block 6: 리서치 결합
관찰자 메타 계층       ←→  졸업 후: Plugin 배포
```

**기존 교육법과의 차이:**
- PBL(프로젝트 기반 학습): 학생이 프로젝트를 *한다*
- 사례 기반 학습: 학생이 사례를 *분석한다*
- **EGL**: 실제 프로젝트의 시간순 진화를 *재현한다* (시간 진화 = 커리큘럼)

---

### 2. 강제 게이트 (Mandatory Gates — STOP Protocol)

> "다음 시대로 진입하려면, 현재 시대의 게이트를 통과해야 한다."

각 학습 블록은 반드시 **2턴 구조**를 따릅니다:

```
Phase A: 설명 + 실습 안내 → STOP (여기서 반드시 멈춤)
          ↓ (사용자가 실습 후 돌아옴)
Phase B: 퀴즈 + 피드백 → 다음 블록 안내
```

이것은 *권장*이 아닌 *아키텍처*입니다.
콘텐츠가 물리적으로 다음 단계로 진행할 수 없도록 구조적으로 차단합니다.

**기존 교육법과의 차이:**
- 완전학습(Bloom): 평가 후 진행을 *권장*
- **EGL**: 평가 후 진행을 *시스템이 강제* (소프트웨어 게이트 패턴)

---

### 3. 재귀적 자기참조 (Recursive Self-Reference)

> "도구가 자기 자신을 가르친다. 도구 = 교사 = 학습 대상."

EGL에서는 학습 도구, 교사, 학습 대상이 동일한 엔티티입니다:

```
Claude Code (도구)  ──→  Claude Code를 가르침 (교사)
     ↑                         ↓
     └──── Claude Code에 대해 학습 (학습 대상) ←─┘
```

컴퓨팅에서 "자기 자신을 로드하는 시스템"을 **부트스트래핑(bootstrapping)**이라 하듯이,
EGL은 교육의 부트스트래핑입니다.

**기존 교육법과의 차이:**
- 구성주의(Papert의 Logo): Logo *를 통해* 수학을 배우지만, Logo *자체*를 가르치지 않음
- Learning by Teaching: 학생이 *다른 학생*을 가르침
- **EGL**: 도구가 *자기 자신*에 대해 *자기 자신을 통해* 가르침 (3중 재귀)

---

### 4. 진화 메타포 (Evolution Metaphor)

> "게임을 플레이하는 것이 아니라, 게임의 진화 구조를 차용한다."

마인크래프트의 자원 계층(흙→돌→철→다이아→네더라이트)을
소프트웨어 아키텍처의 복잡도 계층에 매핑합니다.

```
🏠 흙집       →  bash, 절차적 스크립트
⛏️ 석기       →  if/else, 조건문 코딩
🗡️ 청동기     →  역할 분업, 멀티에이전트
⚔️ 철기       →  도메인 특화, 상태 머신
💎 다이아몬드  →  LLM 통합, 자연어 판단
🟣 네더라이트  →  RAG + 경험 메모리
🌐 메타       →  관찰자 계층, 시스템 모니터링
```

**기존 교육법과의 차이:**
- 게이미피케이션: 게임 *속에서* 학습하거나, 게임 *메커닉*(뱃지, 포인트)을 추가
- **EGL**: 게임의 *내부 진화 논리*를 완전히 다른 도메인의 구조적 뼈대로 사용

---

### 5. RAG-as-Pedagogy (기술 패턴의 교육적 자각)

> "RAG가 지식을 필요할 때만 검색하듯, 교육도 필요한 블록만 로드한다."

EGL은 자신이 가르치는 기술 패턴(RAG)을 교육 방법론 자체에 적용합니다:

```
RAG 패턴 (기술)                    EGL 패턴 (교육)
─────────────────────────────────────────────────────
knowledge.json에서 관련 지식 검색  →  references/에서 관련 블록만 로드
메시지에 "철" → 제련 정보만 주입   →  Block 3 요청 → Block 3 참조만 로드
코드 수정 없이 지식 파일 추가      →  프롬프트 수정 없이 참조 파일 추가
```

**기존 교육법과의 차이:**
- Progressive Disclosure(Nielsen): 복잡성을 점진적으로 노출 (UX 원칙)
- JIT Learning: 필요할 때 콘텐츠 전달 (시간 기반)
- **EGL**: 기술 도메인의 패턴(RAG)을 *자각적으로* 교육 설계에 적용 (메타 자기참조)

## 적용 조건

EGL이 효과적으로 작동하려면 다음 조건이 필요합니다:

1. **실제 프로젝트 진화 이력**: 점진적으로 복잡해진 실제 프로젝트가 존재해야 함
2. **자기참조 가능한 도구**: 학습 도구가 자기 자신을 가르칠 수 있어야 함 (AI 도구)
3. **게이트 강제 메커니즘**: STOP 프로토콜을 시스템 수준에서 강제할 수 있어야 함
4. **참조 가능한 지식 구조**: RAG처럼 블록별로 참조 파일을 분리할 수 있어야 함
5. **진화 메타포**: 학습자가 직관적으로 이해할 수 있는 진화 비유가 존재해야 함
